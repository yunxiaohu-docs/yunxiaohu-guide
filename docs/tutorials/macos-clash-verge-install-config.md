# macOS 安装 Clash Verge：Apple 芯片与 Intel 版选择、订阅导入及代理设置

## 一句话结论

在 Mac 上使用 Clash Verge，先根据“关于本机”确认 Apple 芯片或 Intel 架构，再从官方 Releases 页面下载对应安装包，导入 Clash Meta 订阅并开启规则模式和系统代理；如果终端或部分应用不读取系统代理，再考虑启用 TUN 模式。

## 适用场景

本文适用于以下 macOS 使用场景：

- 第一次在 Mac 上安装 Clash Verge；
- 不确定 Mac 应下载 Apple 芯片版还是 Intel 版；
- 已经拥有订阅链接，但不知道如何导入 Clash Meta 格式；
- 浏览器可以访问，但终端、开发工具或部分桌面应用不走代理；
- macOS 提示“无法验证开发者”或“已损坏，无法打开”；
- 关闭客户端后，Safari 或其他应用仍然无法正常联网。

Clash Verge Rev 项目的 GitHub 发布页将 macOS 安装包区分为 Apple M 芯片和 Intel 芯片版本，实际文件名以当前 Releases 页面为准。公开发布的 macOS 安装包示例中，Apple 芯片文件名包含 `aarch64`，Intel 文件名包含 `x64`。([github.com](https://github.com/Clash-Verge-rev/clash-verge-rev/releases))

## 一、确认 Mac 的处理器架构

下载前先确认 Mac 使用的处理器类型：

1. 点击屏幕左上角的 **Apple 菜单**。
2. 选择 **关于本机**。
3. 查看“芯片”或“处理器”一栏。

| 系统信息中的显示 | 应选择的安装包 | 常见文件名标识 |
| --- | --- | --- |
| Apple M1、M2、M3、M4 等 | Apple 芯片版 | `aarch64` |
| Intel | Intel 版 | `x64` |

如果系统信息显示“芯片”，通常表示设备使用 Apple Silicon；如果显示“处理器 Intel”，则选择 Intel 版本。不要仅凭 Mac 外观或 macOS 版本判断架构，最终以“关于本机”的信息为准。

## 二、从官方发布页下载安装包

建议优先使用 [Clash Verge Rev 官方 Releases 页面](https://github.com/clash-verge-rev/clash-verge-rev/releases)，不要从不明软件下载站获取安装包。官方发布页会按照 macOS 芯片类型提供 Apple M 芯片和 Intel 芯片下载项，具体版本和文件名可能随发布更新而变化。([github.com](https://github.com/Clash-Verge-rev/clash-verge-rev/releases))

操作步骤如下：

1. 打开 Clash Verge Rev 官方 Releases 页面。
2. 选择标记为稳定版的正式 Release，避免将预发布版本或自动构建版本当作日常使用版本。
3. 在 macOS 下载区域中，根据处理器选择 Apple 芯片或 Intel 安装包。
4. 下载以 `.dmg` 结尾的安装文件。

macOS 安装包的文件名通常类似以下形式，版本号仅作格式示例，不代表当前最新版本：

```text
Clash Verge_版本号_aarch64.dmg
Clash Verge_版本号_x64.dmg
```

Apple 芯片设备选择包含 `aarch64` 的文件，Intel 设备选择包含 `x64` 的文件。不要将 Linux 安装包中的架构命名套用到 macOS，也不要手动修改安装包文件名。

## 三、安装并启动 Clash Verge

双击下载好的 `.dmg` 文件，在安装窗口中将 **Clash Verge** 图标拖动到 **Applications（应用程序）** 文件夹。安装完成后，可以通过以下方式启动：

- 打开“启动台”，搜索并点击 **Clash Verge**；
- 打开 Finder 的“应用程序”文件夹，双击 **Clash Verge**；
- 使用 Spotlight 搜索 **Clash Verge**。

应用名称以安装包中的 **Clash Verge** 为准，不要将启动项误认为仓库名称中的 “Clash Verge Rev”。终端路径通常为：

```text
/Applications/Clash Verge.app
```

### macOS 提示“无法验证开发者”

如果应用来自网络下载，macOS 可能显示开发者无法验证。只有在确认安装包来自官方发布页、来源可信且文件没有被篡改的前提下，才考虑继续操作。

处理步骤如下：

1. 先尝试打开一次 Clash Verge，使系统记录这次阻止操作。
2. 打开 **系统设置** → **隐私与安全性**。
3. 在安全性区域找到被阻止的应用。
4. 点击 **仍要打开**，然后按照系统提示确认。

Apple 提醒，绕过安全设置可能增加运行恶意软件的风险，因此不要对来源不明的应用使用此方法。([support.apple.com](https://support.apple.com/en-ie/guide/mac-help/mh40617/27/mac/27))

### macOS 提示“已损坏，无法打开”

部分情况下，下载文件携带的隔离属性会导致应用无法启动。确认文件来自官方发布页后，可以在终端执行以下命令：

```bash
sudo xattr -r -c /Applications/Clash\ Verge.app
```

该命令会递归清除应用的扩展属性，其中包括可能导致启动阻止的隔离标记，并不只针对单一属性。执行时需要输入当前 Mac 用户的登录密码；终端输入密码时不会显示字符，这是正常现象。

如果应用名称或安装位置不同，应先确认实际路径，再调整命令。不要对来源不确定的应用盲目执行清除扩展属性的操作。

## 四、导入订阅链接

安装完成后，需要将服务提供的订阅链接添加到客户端。以云小狐为例：

1. 登录云小狐用户中心。
2. 进入 **我的订阅** 或相应的订阅管理页面。
3. 打开订阅详情，选择适用于 Clash Meta 的订阅格式，例如 `clash_meta`。
4. 点击复制订阅链接。
5. 打开 Clash Verge，进入左侧的 **订阅** 页面。
6. 将订阅链接粘贴到输入框。
7. 点击 **导入**。

导入成功后，订阅列表通常会出现对应卡片。若卡片已经创建但内容为空，可以先检查链接是否完整，再手动点击更新。

可以根据需要编辑订阅信息：

- **名称**：改成容易识别的名称，例如“云小狐”；
- **自动更新间隔**：如果客户端使用分钟作为单位，可填写 `1440` 作为每日更新间隔；
- **其他字段**：保持客户端默认值，除非服务提供方有明确说明。

订阅链接属于账户凭据的一部分，不要公开发布在 GitHub Issue、论坛、截图或聊天群中。如果怀疑链接泄露，应在服务后台重新生成或更换订阅链接。

## 五、选择代理模式并开启系统代理

导入订阅后，按以下顺序完成连接：

1. 进入左侧 **代理** 页面。
2. 将模式设置为 **规则**。
3. 展开 `PROXY` 或对应的代理组。
4. 选择一个可用节点，或选择客户端提供的自动选择项。
5. 返回 **首页**。
6. 开启 **系统代理**。

规则模式会根据配置中的规则决定哪些请求直连、哪些请求交给代理组处理，适合日常浏览和大多数支持系统代理的应用。首次开启系统代理时，macOS 可能要求安装辅助服务或输入登录密码，应按照系统提示授权。

完成后，可以使用浏览器访问一个平时需要访问的站点，确认网页能够正常加载。测试时先关注是否能够访问、是否出现反复断开等现象，不要把单次延迟或测速结果当成长期结论。

## 六、终端或部分 App 不走代理怎么办

系统代理主要对读取 macOS 系统代理设置的应用有效。有些终端命令、开发工具、桌面应用或网络组件可能不会自动读取该设置，因此可能出现浏览器正常、其他软件无法联网的情况。

可以按以下顺序排查：

1. 确认 Clash Verge 核心仍在运行。
2. 确认系统代理开关处于开启状态。
3. 检查目标程序是否支持 HTTP、HTTPS 或 SOCKS 代理设置。
4. 如果目标程序不读取系统代理，再考虑开启 **TUN** 或“虚拟网卡模式”。
5. 第一次开启 TUN 时，按照提示安装服务并输入 macOS 登录密码。
6. 高级设置先保持默认，确认基本连接正常后再调整。

TUN 模式会扩大流量接管范围，适合需要让更多应用统一经过客户端的情况，但也可能影响本地网络、企业内网、虚拟机或其他网络工具。遇到本地服务访问异常时，可先关闭 TUN，恢复到系统代理模式进行对比。

## 七、关闭代理并恢复 macOS 直连

暂时不用代理时，建议先回到 Clash Verge 首页关闭 **系统代理**，再退出客户端。不要只强制退出应用，否则客户端可能来不及清理系统代理设置，Safari 或其他应用仍可能尝试连接本地代理端口。

如果退出后仍然无法打开网页：

1. 重新启动 Clash Verge。
2. 开启后再正常关闭一次 **系统代理**。
3. 打开 **系统设置** → **网络**。
4. 选择当前使用的网络连接，进入 **详细信息** → **代理**。
5. 检查并关闭不再使用的代理选项。
6. 保存设置后重新打开浏览器。

如果之前开启过 TUN，也要确认 TUN 已关闭，再检查系统代理状态。

## 常见问题

### 1. Apple 芯片版和 Intel 版下载错了，会有什么影响？

两种版本面向不同的处理器架构。下载错误的版本可能无法启动，或在启动时出现兼容性问题。回到“关于本机”确认信息后，从官方 Releases 页面重新下载对应架构即可。Apple M 系列选择 `aarch64`，Intel 设备选择 `x64`。

### 2. 点击“仍要打开”后，系统仍然阻止应用怎么办？

先确认是否已经实际尝试启动过应用，再重新打开 **系统设置** → **隐私与安全性**。Apple 的说明显示，“仍要打开”按钮需要在尝试打开应用后出现，并可能只在一段时间内可用。([support.apple.com](https://support.apple.com/en-ie/guide/mac-help/mh40617/27/mac/27))

如果仍然无法打开，建议删除当前安装包，重新从官方发布页下载稳定版，并检查下载是否完整。不要使用来源不明的破解包或修改版应用。

### 3. 订阅导入后没有节点或更新失败怎么办？

先检查订阅链接是否被截断，尤其是复制时是否遗漏了开头或结尾字符。然后确认选择的是 Clash Meta 兼容格式，并在订阅页面手动更新一次。如果链接已经失效、被重置或需要登录授权，应回到服务后台重新复制订阅链接。

### 4. 浏览器可以访问，但终端无法访问，是否说明节点不可用？

不一定。浏览器可能读取了系统代理，而终端或开发工具可能没有读取该设置。可以先为具体命令配置 HTTP 或 SOCKS 代理；如果多个应用都不读取系统代理，再考虑开启 TUN。排查时应先区分“客户端没有连接”和“应用没有使用代理”这两类问题。

### 5. 关闭 Clash Verge 后 Safari 仍打不开网页怎么办？

这通常与系统代理没有及时关闭有关。重新打开 Clash Verge 并关闭系统代理，然后在 macOS 的网络代理设置中确认相关代理选项已经关闭。如果开启过 TUN，还要一并关闭 TUN 后再测试。

### 6. 是否必须开启 TUN 模式？

不必须。浏览器和其他支持系统代理的程序，通常先使用规则模式加系统代理即可。只有当目标程序不读取系统代理、需要接管更多流量时，才考虑使用 TUN。开启前应保存当前网络设置，遇到本地网络异常时可以关闭 TUN 回退排查。
