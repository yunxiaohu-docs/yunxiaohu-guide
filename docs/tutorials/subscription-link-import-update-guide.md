# 订阅链接怎么导入与更新：Clash、sing-box 客户端完整指南

## 一句话结论

订阅链接本质上是客户端用来获取远程配置或节点信息的地址；正确操作顺序是先找到完整链接，再选择与客户端匹配的格式，完成导入和首次更新，之后在续费或配置变化时更新原有订阅，而不是反复创建多个重复配置。

## 适用场景

本文适用于以下情况：

- 第一次使用订阅链接，不知道应该从哪里复制。
- 已经拿到链接，但不确定应该导入 Clash、sing-box 还是通用格式。
- 客户端显示订阅已添加，却没有节点或配置内容。
- 续费后客户端仍然显示旧的流量、到期时间或节点列表。
- 想设置自动更新，但不清楚更新频率和单位。
- 订阅链接曾经被发到截图、群聊、论坛、工单或公开代码仓库中。

订阅链接通常带有用于访问配置的令牌或查询参数，应当按照账号凭据保存。不要把完整链接公开发布，也不要粘贴到在线转换站、公共日志、公开仓库或不可信的聊天窗口中。使用网络加速服务时，请遵守当地法律法规。

## 一、在用户中心找到完整订阅链接

不同平台的页面名称可能不同，但一般可以按照下面的路径查找：

1. 登录用户中心。
2. 打开「我的订阅」「订阅管理」或套餐列表。
3. 找到正在使用的套餐并进入详情页。
4. 查找「订阅链接」「复制订阅」「订阅地址」或二维码区域。
5. 根据目标客户端选择对应格式，然后复制完整地址。

复制时建议使用页面提供的复制按钮，不要手动选取长文本。不要删除问号、等号、斜杠或其他查询参数，也不要把浏览器地址栏中的普通网页地址误认为订阅地址。

如果使用了剪贴板管理器，导入完成后应清理剪贴板历史。提交问题或上传日志时，只保留域名和脱敏后的部分字符，不要直接提供完整订阅地址。

## 二、根据客户端选择订阅格式

订阅格式指服务器返回内容的结构，不是客户端名称的另一种写法。客户端与格式不匹配时，可能出现导入失败、配置解析错误、节点为空或更新后分组异常。

| 使用场景 | 选择原则 | 说明 |
| --- | --- | --- |
| Clash Meta 或 Mihomo 兼容客户端 | 选择页面提供的 Clash Meta、Mihomo 或同类格式 | 具体名称以订阅页面和客户端当前版本为准 |
| sing-box 兼容客户端 | 选择 sing-box 格式 | 客户端需要支持对应的配置结构 |
| v2rayN、v2rayNG 或其他通用客户端 | 选择页面提供的通用节点或分享链接格式 | 支持的协议和导入方式取决于客户端版本 |
| 手机客户端 | 优先使用客户端支持的订阅类型或一键导入入口 | 一键导入失败时改用复制粘贴 |

Clash Verge Rev 官方仓库将其介绍为基于 Tauri 的 Clash Meta 图形客户端，支持 Windows、macOS 和 Linux；Clash Meta for Android 官方仓库则说明其为 Android 图形客户端；v2rayN 官方仓库说明该项目面向 Windows、Linux 和 macOS，并支持 Xray、sing-box 等核心。客户端菜单和订阅格式名称可能随版本变化，因此遇到选项不一致时，应以当前版本界面和官方文档为准。([github.com](https://github.com/Clash-Verge-rev/clash-verge-rev))

如果正在使用云小狐提供的订阅服务，应先在订阅详情页确认实际提供的格式，再按照客户端类型选择，不要只根据链接后缀或他人截图判断。

## 三、导入订阅链接

### 方法 1：复制粘贴导入

复制粘贴最适合首次导入和故障排查，因为每一步都能单独确认：

1. 在订阅详情页选择所需格式并点击复制。
2. 打开客户端的订阅管理、配置文件、远程配置或订阅分组页面。
3. 新建订阅项目。
4. 将完整地址粘贴到 URL、订阅地址或远程配置地址输入框。
5. 保存订阅。
6. 点击「更新」「刷新」「Update」或含义相近的按钮。
7. 等待下载完成，进入代理列表或节点列表选择内容。
8. 按客户端设计打开系统代理、VPN 或连接开关。

排查时可以把流程拆成四个阶段：

- **地址是否保存**：输入框中是否保留了完整 URL。
- **请求是否成功**：更新时是否出现网络、TLS、DNS 或 HTTP 错误。
- **内容是否解析**：客户端是否识别返回内容。
- **节点是否被选中**：订阅更新成功后，是否实际选择了代理组或节点。

“订阅已添加”只代表客户端保存了地址，不一定代表已经成功下载和解析。

### 方法 2：二维码导入

如果订阅页面提供二维码，可以在电脑上打开页面，再使用手机客户端的扫码功能导入。扫码后仍应检查以下项目：

- 扫描结果是否是订阅地址，而不是普通网页地址。
- 客户端是否选择了正确的配置类型。
- 导入后是否真正执行了一次更新。
- 更新完成后是否能在配置或节点列表中看到内容。

二维码识别失败时，建议改用复制粘贴。屏幕反光、浏览器缩放、二维码分辨率不足或相机权限关闭，都可能导致扫码失败。

### 方法 3：手机浏览器一键导入

部分订阅页面会提供「导入到客户端」「打开 App」或类似按钮。点击后可能出现以下结果：

- 客户端直接打开并创建订阅。
- 系统只把地址复制到剪贴板。
- 浏览器提示没有可处理该协议的应用。
- 客户端打开了，但没有自动执行更新。

如果没有自动导入，不要连续重复点击。回到客户端的订阅管理页面，手动粘贴地址并执行更新，通常更容易判断问题发生在哪一步。

部分客户端支持通过 URL Scheme 唤起导入页面。下面的命令使用示例地址，不会暴露真实令牌：

```bash
python3 -c 'from urllib.parse import quote; u="https://example.com/subscription?token=REPLACE_ME%22; print("clash://install-config?url=" + quote(u, safe=""))'
```

是否能自动打开客户端，取决于操作系统、浏览器以及客户端是否注册了对应协议。生成 URL Scheme 并不代表所有客户端都支持该方式。

## 四、续费后先更新原有订阅

续费或购买流量包后，通常应先在原有订阅分组中执行更新，不要马上删除配置并重复创建多个同名订阅。推荐按以下顺序操作：

1. 完成续费或流量包购买。
2. 打开客户端中原有的订阅分组。
3. 手动点击更新或刷新。
4. 查看最近一次成功更新时间。
5. 检查到期时间、流量信息和节点列表是否发生变化。
6. 如果仍然显示旧数据，完全退出客户端后重新打开，再更新一次。

如果设备中存在多个同名订阅，应确认当前查看的是正在使用的分组。重复导入同一个地址可能会创建多个副本，后续容易误判更新没有生效。

## 五、什么时候需要更新订阅

以下情况适合手动更新：

- 续费或购买流量包后，需要刷新账号状态。
- 节点列表、代理分组或远程配置发生变化。
- 客户端显示的更新时间明显过旧。
- 远程地址可以访问，但节点列表与预期不一致。
- 客户端提示订阅内容下载失败，需要重新发起请求。

如果客户端支持自动更新，可以考虑设置为每天一次。原说明中的示例使用 `1440` 分钟表示一天，但不同客户端的输入单位可能是分钟、小时或其他形式，设置前应确认当前界面的单位。不要把一个软件的配置字段或单位直接套用到另一个软件。

### 使用 curl 检查订阅地址

检查远程订阅地址时，不建议默认使用 `curl -I`。该选项会发送 HTTP HEAD 请求，而有些服务器只处理 GET，因此可能返回 `405 Method Not Allowed`、空响应，或者与客户端实际下载结果不同。

更接近客户端下载行为的基础检查方式是普通 GET 请求，同时把响应正文丢弃、把响应头输出到终端：

```bash
curl -L -sS -o /dev/null -D - --max-redirs 5 'https://example.com/subscription?token=REPLACE_ME%27
```

curl 官方手册说明，`-D -` 会把响应头写到标准输出，`-o` 可以将响应正文写入指定文件，`-L` 会跟随重定向，`--max-redirs` 可以限制重定向次数。([curl.se](https://curl.se/docs/manpage.html?data1=sru))

参数含义如下：

- `-L`：跟随服务器返回的重定向。
- `-sS`：隐藏进度信息，但在发生错误时保留错误提示。
- `-o /dev/null`：丢弃响应正文，避免配置内容直接显示在终端。
- `-D -`：将响应头输出到终端。
- `--max-redirs 5`：最多跟随 5 次重定向。

Windows 命令提示符可以使用 `NUL` 代替 `/dev/null`：

```bat
curl -L -sS -o NUL -D - --max-redirs 5 "https://example.com/subscription?token=REPLACE_ME%22
```

检查时重点观察 HTTP 状态码、重定向情况，以及是否出现 DNS、TLS 或连接错误。该命令只能帮助判断请求层面的基本结果，不能证明返回内容一定符合 Clash、sing-box 或其他客户端的配置格式。不要在包含真实令牌的命令中使用 `-v` 后将输出公开，也不要把完整 URL 保存到公共日志中。

## 六、订阅链接泄露后的处理

如果完整地址曾经出现在公开仓库、论坛、群聊、截图、在线转换页面或不可信设备中，应按照已经泄露处理，而不是继续观察是否有人使用。

建议按以下步骤处理：

1. 登录用户中心并进入订阅详情。
2. 查找「轮换分享链接」「重置链接」或含义相近的功能。
3. 确认轮换操作，使旧地址失效。
4. 复制新生成的地址。
5. 在自己的手机、电脑和平板上重新添加新订阅。
6. 删除旧订阅分组，避免客户端继续请求失效地址。
7. 检查近期流量、设备和登录记录；发现异常时保存时间、设备名称和客户端日志。

如果页面没有提供轮换功能，应联系服务提供方申请重置。提交问题时只提供脱敏信息，例如客户端名称、系统版本、错误提示、HTTP 状态码和隐藏令牌后的 URL 片段。

## 常见问题

### 1. 导入后提示解析失败，应该先查什么？

先确认复制的是完整订阅地址，而不是普通网页地址；然后检查查询参数是否被截断，地址中是否混入空格或换行，以及选择的格式是否与客户端匹配。手动更新一次并查看客户端日志。如果请求成功但解析失败，可以回到订阅页面更换为客户端支持的格式。

### 2. 订阅已经添加，但节点列表为空怎么办？

先确认更新请求是否成功，再判断是格式问题还是返回内容问题。可以查看最近一次更新时间、HTTP 状态码、客户端日志和当前订阅分组。使用 curl 检查时，应优先使用普通 GET 请求，不要只用 HEAD 请求判断订阅是否可用。即使服务器返回了内容，也仍然要确认内容符合客户端支持的配置结构。

### 3. 续费后仍显示旧的到期时间，是否必须重新复制链接？

通常先更新原有订阅即可。确认是否更新了正确的分组，设备中是否存在多个同名订阅，以及客户端是否显示最近一次成功更新时间。退出并重新打开客户端后再更新一次；仍未变化时，再联系服务提供方核对账号状态或订阅地址是否失效。

### 4. 自动更新设置多久合适？

日常使用可以考虑每天更新一次，但最终应以客户端界面显示的单位和服务端说明为准。更新过于频繁通常没有必要，也可能受到客户端、网络环境或服务器请求限制影响。如果客户端支持读取远程更新间隔，不要把其他软件的配置字段直接复制过来。

### 5. 一个订阅可以在多台自己的设备上使用吗？

根据原说明，一个订阅可以导入多台设备，设备数量不限，所有设备共用同一套餐流量。这里的“可以导入”不等于可以把链接公开分享；完整订阅地址仍应只保存在自己的手机、电脑或平板上。其他服务的设备数量、流量计算方式和使用限制可能不同，应以各自的服务说明为准。

### 6. 更新订阅时是否必须先连接代理？

不一定。更新请求如何发出，取决于客户端设置、系统代理、当前网络和订阅地址本身。遇到更新失败时，应先查看日志并检查订阅地址是否可以访问，再判断是否需要切换网络路径。不要只因为节点连接失败，就认定订阅地址一定失效。

### 7. curl 能否确认订阅内容一定可用？

不能。curl 可以帮助检查 DNS、TLS、连接、重定向和 HTTP 响应等请求层面信息，但不会替代客户端对配置结构的解析。最终仍应在目标客户端中执行一次更新，并查看配置是否成功加载。
