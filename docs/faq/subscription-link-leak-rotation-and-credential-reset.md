# 订阅链接泄露后的处理：分享链接轮换与接入凭证重置

## 一句话结论

订阅链接被误发、截图未打码，或出现无法解释的流量消耗时，应尽快轮换分享链接；如果怀疑别人已经把节点配置导入客户端，仅轮换链接可能不够，还应通过工单申请轮换接入凭证，并在所有自有设备上重新导入订阅。

## 适用场景

本文适用于以下情况：

- 把完整订阅链接发到了群聊、论坛、评论区或工单中；
- 截图时没有遮挡订阅地址、二维码或包含完整链接的页面；
- 发现流量消耗异常，但暂时无法确认是否有人使用了订阅；
- 更换手机、电脑或平板，旧设备已经送人、出售或无法继续管理；
- 已经点击轮换分享链接，但旧设备中的节点仍然可以使用；
- 需要区分“订阅地址失效”和“已经导入的节点配置失效”这两种情况。

订阅链接通常不仅是一个普通网页地址，还可能包含用于获取配置的访问凭证。因此，不能把它当成可以公开发布的普通链接处理。根据通用的密钥管理原则，疑似泄露的凭证应及时撤销或轮换，而不是只删除聊天记录或截图。([docs.github.com](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository?ref=techblog.kevinburns.de))

## 先区分两种重置对象

| 对象 | 主要作用 | 适合处理的问题 | 完成后是否要重新导入 |
| --- | --- | --- | --- |
| 分享链接 | 控制客户端以后从哪里获取订阅 | 链接被转发、发布或截图泄露 | 是，所有设备都应替换旧地址 |
| 接入凭证 | 控制已经获取到的节点配置能否继续接入 | 怀疑他人已经导入节点并持续使用 | 是，所有客户端都要重新导入 |

可以把两者理解为两个不同阶段：分享链接负责“下载配置”，接入凭证负责“使用配置”。如果只是担心链接被别人看到，通常先轮换分享链接；如果已经出现明显异常，或怀疑配置已经被导入其他设备，则应同时处理接入凭证。

## 处理步骤

### 第一步：立即停止继续传播

先不要在群聊、论坛、工单或公开评论中再次发送完整链接，也不要为了求助而上传包含二维码的原始截图。需要向客服说明情况时，只描述泄露时间、泄露渠道和异常现象，避免把完整订阅地址直接贴出。

建议先记录以下信息：

- 大致泄露时间；
- 泄露位置，例如群聊、截图、浏览器历史记录或旧设备；
- 是否有人可能已经保存或导入链接；
- 是否存在流量消耗异常；
- 当前仍在使用订阅的设备清单。

如果需要在本地记录链接，可以只保留域名和末尾几位字符，例如：

```text
https://example.com/********************7f3a
```

不要把真实链接写入公开的 Markdown、Issue、代码仓库、网盘分享说明或日志文件。对于已经提交到代码仓库的敏感凭证，单纯删除文件或新增一次提交并不能阻止旧凭证继续被使用，正确顺序应是先撤销或轮换，再视情况清理仓库历史。([docs.github.com](https://docs.github.com/en/code-security/tutorials/remediate-leaked-secrets/remediating-a-leaked-secret))

### 第二步：自行轮换分享链接

大多数“链接被看到”的情况，可以先自行轮换分享链接。操作路径如下：

1. 登录用户中心。
2. 进入“我的订阅”。
3. 点击“查看详情”。
4. 滚动到页面底部，找到“轮换分享链接”。
5. 确认轮换操作。
6. 在“订阅链接”区域复制新的地址。
7. 在自己的每台设备上删除旧订阅，或直接替换客户端中的订阅地址。
8. 手动执行一次更新，确认客户端读取的是新地址。

轮换成功后，旧分享链接会立即失效，其他人不能再通过旧地址更新订阅。需要注意的是，已经下载到某台设备中的旧配置不一定会因为分享链接失效而自动消失，所以不能把“旧链接无法更新”和“旧配置无法连接”视为同一件事。

### 第三步：在各客户端替换订阅地址

不同客户端的按钮名称可能不同，但处理逻辑基本一致：删除旧订阅、添加新订阅、执行更新、确认配置生效。

建议按以下顺序操作：

1. 打开客户端的订阅或配置列表。
2. 删除旧订阅，或者编辑订阅项目并替换 URL。
3. 粘贴新的分享链接。
4. 保存后执行“更新订阅”“重新获取”或同义操作。
5. 在配置列表中确认更新时间已经变化。
6. 选择新配置，再恢复原来的规则、全局或直连模式。

如果使用云小狐提供的订阅服务，轮换后应优先完成常用手机、电脑和平板的替换，再处理不常用或暂时离线的设备。

在基于 mihomo 的客户端中，官方项目与内核文档可从 [MetaCubeX/mihomo](https://github.com/MetaCubeX/mihomo) 获取；使用 sing-box 的用户可参考 [SagerNet/sing-box](https://github.com/SagerNet/sing-box)。第三方客户端的导入界面可能不同，但不要把新链接复制到不可信的转换网站或陌生网页中。([github.com](https://github.com/orgs/MetaCubeX/repositories))

### 第四步：判断是否需要轮换接入凭证

以下情况建议提交工单申请轮换接入凭证：

- 流量消耗明显异常，且无法由自己的设备使用解释；
- 订阅链接曾经公开发布，且已经过了一段时间；
- 旧手机、旧电脑已经转交他人，设备中可能还保留着完整配置；
- 自行轮换分享链接后，仍然怀疑旧配置可以继续使用；
- 不能确认订阅是否已经被其他人导入。

提交工单时，可以说明“需要轮换接入凭证”，并补充泄露的大致时间和影响范围。不要在工单正文中发送完整订阅链接、二维码或节点配置文件。

接入凭证轮换完成后，所有自有客户端都要重新导入订阅。原有配置、旧节点列表或旧缓存如果仍然保留，可能会造成“已经处理完成但客户端仍显示旧内容”的误判，因此建议先删除旧配置，再导入新链接。

### 第五步：完成本地清理与复核

完成轮换后，按设备逐台检查：

- 浏览器收藏夹、历史记录和下载文件中是否保存了旧链接；
- 聊天软件的“文件”“收藏”或置顶消息中是否还有原始截图；
- 客户端订阅列表中是否仍有旧地址；
- 是否存在导出的 YAML、JSON、订阅二维码或配置备份；
- 自动更新任务、脚本和系统服务是否仍引用旧配置；
- 家庭成员或自己管理的其他设备是否还没有更新。

如果曾经把链接写入 Git 仓库，可以先用以下命令查找疑似 URL；命令只用于定位，不会自动修改文件：

```bash
git grep -n -E 'https?://[^[:space:]"'"'<>]+'
```

找到后，应先在服务端轮换或撤销旧凭证，再决定是否清理 Git 历史。直接改写历史会影响提交哈希、协作者本地副本和分支同步，适合在确认影响范围后处理。([docs.github.com](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository?ref=techblog.kevinburns.de))

## 常见问题

### 1. 只轮换分享链接，旧设备上的配置会自动失效吗？

不一定。分享链接主要影响客户端后续获取订阅的入口。已经下载到设备中的配置可能仍然存在，因此如果怀疑他人已经导入节点配置，不能只做分享链接轮换，还应申请轮换接入凭证，并让自己的设备重新导入。

### 2. 我只是把链接发给了自己的另一台设备，需要重置吗？

如果链接只在自己可控的设备之间传输，且没有公开或发送给他人，通常不必因为正常使用而重置。但如果旧设备已经出售、送人、维修，或者设备上的配置没有删除，就应至少轮换分享链接；无法确认旧配置是否仍被使用时，再申请轮换接入凭证。

### 3. 轮换后客户端更新失败，是否说明新链接无效？

不一定。先检查是否仍复制了旧链接，客户端是否缓存了旧订阅项目，网络是否可以正常打开订阅地址，以及客户端是否支持该订阅格式。可以删除旧订阅项目后重新添加，避免编辑界面没有真正保存新地址。不要通过公开的在线转换服务反复粘贴完整链接。

### 4. 需要把所有客户端卸载重装吗？

通常不需要。重点是删除旧订阅或旧配置，再导入新的订阅地址。如果已经轮换接入凭证，建议不要继续使用旧的 YAML、JSON、二维码或导出的配置文件，以免客户端重新加载旧凭证。

### 5. 流量异常一定代表订阅链接泄露了吗？

不一定。异常可能与设备重复更新、家庭成员使用、自动化任务、旧设备未退出或统计延迟有关。但在无法解释异常来源时，应按凭证可能泄露处理：先轮换分享链接，必要时再轮换接入凭证，并核对所有设备。

### 6. 轮换后还需要修改账号密码吗？

分享链接和账号登录密码通常是不同对象。是否需要修改登录密码，要看是否同时怀疑账号密码、邮箱或设备本身被他人获取。如果存在账号被登录、设备丢失等情况，应按照账户安全流程处理，并遵守当地法律法规。
